01

문제와 첫 사용자

AI로 해결하고자 하는 문제 상황 또는 새롭게 시도해보고 싶은 업무/서비스는 무엇인가요?

“하루 종일 바빴는데, 정작 무엇을 했는지 쓰려니 생각나지 않는다.”

첫 사용자는 사내 시스템의 조회·문의 대응을 반복하면서 주간보고를 작성하는 운영·지원 담당자다. Windows와 Chrome을 오가며 자료를 조회하고, 응답을 작성하고, 문서 내용을 보완한다. 이 과정에서 생기는 짧은 문의 대응, 자료 확인, 동료 지원은 업무 티켓이나 개인 메모에 모두 남기기 어렵다. 일을 수행하는 것과 별개로 무엇을 했는지 기억해 기록해야 하는 부담이 있다.

기록에서 빠진 일은 주간·월간 보고와 평가 준비에서도 놓치기 쉽다. 같은 조회와 안내를 반복하고 있어도 개별 요청으로만 기억하면, 어떤 업무를 개선할 수 있을지 발견하기 어렵다. 프로그램별 사용 시간을 알아도 그 안에서 어떤 일을 했는지 설명하려면 추가적인 해석이 필요하다.

WorkMemory AI는 작업 중 자동으로 쌓이는 기록을, 사용자가 이해하고 활용할 수 있는 업무 기억으로 바꾸는 서비스를 제안한다. 먼저 하루의 업무를 복원해 기억에서 빠진 일을 확인하도록 돕는다. 이어서 개별 조회와 응답으로만 여겼던 행동들이 어떤 반복 업무를 이루는지 보여준다. 사용자가 나중에 기억을 모아 보고를 작성하던 과정을, 작업 기록에서 만들어진 업무 목록을 검토하고 보고에 활용하는 과정으로 바꾼다.

출발점은 기존 work-memory의 Windows 활동 및 Chrome·Windows 앱 상호작용 수집 기능이다. 수집 가능한 범위에서 분석을 시작하고, 모호한 업무는 사용자가 짧게 수정하거나 확인할 수 있게 한다. 별도의 업무 일지를 매번 작성하지 않아도 시작할 수 있는 경험을 목표로 한다.

02

AI 활용 계획

제안한 아이디어를 실현하기 위해 AI를 어떻게 활용할 계획인가요?

① 흩어진 행동을 업무로 복원: “오늘 내가 한 일”

AI가 입력 내용, 클릭한 요소, 프로그램, 발생 시각과 수집 맥락을 함께 분석해 관련 이벤트를 업무 후보로 묶는다. 서로 다른 프로그램에서 이어진 행동도 연결 근거가 있을 때 같은 업무의 일부로 제안한다.

다음은 기능을 설명하기 위한 가상의 기록이다.

관측된 기록 AI가 제안하는 업무 후보
사내 웹페이지에서 설비번호 EQ-102 입력, ‘조회’ 클릭 EQ-102 관련 정보 조회
이후 수집이 지원되는 응답 작성 필드에서 ‘EQ-102 조회 조건을 확인해 주세요’ 입력값 변경 관측 앞선 조회와 관련된 문의 응답 작성 가능성

사용자는 두 기록을 보고 ‘설비 조회 문의 대응’이라는 하나의 업무로 확인하거나, 잘못 연결된 항목을 제외할 수 있다. 원본 이벤트 대신 하루의 업무 목록을 먼저 보고, 선택한 카드 묶음을 한 번에 확인한다. 근거는 필요할 때만 펼치고, 모호한 제목이나 연결만 짧게 고친다. 여러 번의 입력 수정과 클릭을 곧바로 여러 건의 업무로 세지 않는다. 고급 합치기·분리 편집은 후속 기능으로 확장한다.

AI의 핵심 역할은 표현과 목적을 함께 해석하는 것이다. ‘날짜 범위를 바꿔 조회’와 ‘조회 기간 안내’를 같은 유형의 지원 업무 후보로 연결하고, 같은 설비번호가 있어도 ‘정기점검 자료 작성’은 별도 목적의 업무로 구분하도록 한다. 이런 사례를 포함해 프로그램별 시간 집계와 공통 단어만으로 묶은 결과보다 업무 의미를 잘 복원하는지 검증한다.

② 빠뜨린 일과 인식하지 못했던 반복 업무 발견: “이런 일을 계속하고 있었네요”

발견은 두 단계로 제공한다. 먼저 복원된 업무 목록에서 잊고 있던 문의 대응·자료 확인·지원 업무를 떠올린다. 다음으로 각기 다른 작은 일로 기억했던 기록들이 비슷한 목적의 반복 업무였다는 점을 확인한다. 다음은 여러 날의 가상 기록과 사용자 확인을 전제로 한 대표 결과물이다.

단계 사용자에게 보이는 내용
사용자가 기억한 일 ‘주간 자료 작성’, ‘설비 조회’
기록에서 복원한 일 서로 다른 시점의 조회 조건 확인과 안내 응답 작성 후보
사용자가 확인한 업무 서로 다른 요청에 대한 ‘조회 방법 안내’ 3건. 입력 수정본은 별도 건수로 세지 않음
새롭게 알게 된 점 따로 기록하지 않았던 시스템 사용 지원을 반복해서 맡고 있었음
개선과 보고에 활용 공통 안내문을 검토할 후보로 남기고, 확인된 3건을 근거와 함께 주간보고에 반영

이 비교 목록은 발견을 설명하고 효과를 검증하기 위한 자료다. 실제 사용 때 매일 기억으로 작성한 별도 일지를 요구하지 않는다.

확인된 업무가 누적되면 AI가 비슷한 목적의 작업과 반복되는 처리 흐름을 찾아 개선 후보를 제시한다. 예를 들어 서로 다른 날의 조회·안내 업무가 유사하다면 “비슷한 조회와 안내 흐름이 반복됐습니다. 자주 쓰는 안내문이나 조회 절차를 정리해볼까요?”라고 제안한다. 카드에서 어떤 업무들이 근거인지와 묶은 이유를 확인하고, 잘못 연결된 항목을 제외할 수 있다.

원시 이벤트의 반복과 실제 업무의 반복을 구분한다. 반복 횟수는 사용자가 확인한 업무 단위를 기준으로 집계하며, 아직 확인하지 않은 묶음은 후보로 표시한다. 개선 제안은 업무를 바꿔볼 가설로 제공하고, 절감 시간이나 효과는 실제 적용 후 확인한다.

③ 같은 기억을 기간별 보고로 활용: “이번 주와 이번 달의 나”

사용자가 확인한 업무와 보완한 내용을 바탕으로 AI가 목적에 맞는 보고서 초안을 작성한다. 기간과 서식을 선택해 같은 업무 기록을 여러 번 활용할 수 있게 한다.

결과물 정리할 내용 사용자에게 제공하는 가치
일일 업무 정리 오늘 수행한 업무, 관련 기록, 추가 확인이 필요한 항목 하루를 잊기 전에 짧게 확인하고 수정
주간 업무보고 주요 업무, 사용자 확인 결과·이슈, 진행 내용 지난 기록을 다시 모으는 시간 절약
월간 업무보고 주제별 업무 흐름, 반복 업무, 확인된 변화와 개선 시도 여러 주에 걸친 일을 연결해 한 달의 흐름 파악
향후 평가노트 선택한 기간의 업무·지원·개선 사례와 근거 몇 달 전의 일을 다시 떠올릴 자료 축적

해커톤의 필수 결과물은 근거가 연결된 주간보고 한 종류로 정한다. 일일 정리는 업무 카드 화면으로 제공하고, 월간은 같은 확인 업무를 더 긴 기간으로 묶는 선택 구현 항목으로 둔다. 월간·평가노트까지 이어지는 기억의 축적은 제품의 확장 방향이다.

MVP는 보고의 업무 항목마다 관련 카드와 원본 근거를 연결하고, 문장별 상세 연결은 선택 구현으로 둔다. 완료 여부, 해결 결과, 실제 기여와 다음 계획은 사용자 확인이나 추가 자료가 있을 때 포함한다. 부족한 정보는 보완 항목으로 남기고, 확인되지 않은 후보는 별도로 보여준다. 일상적인 검토는 업무 이름과 묶음을 확인하는 수준으로 시작하고, 결과 설명은 보고에 필요한 시점에 보완할 수 있게 한다.

④ AI 해석을 확인 가능한 결과로 제공

처리 흐름은 로그 정리 → 업무 후보 구성 → 사용자 확인·수정 → 반복 흐름 분석 → 기간별 보고 생성으로 구성한다. 건수·날짜·관측된 활동 시간은 코드로 계산하고, AI는 의미에 따른 묶음·요약·개선 후보·문서 초안을 생성한다. 사용자의 수정 내용을 이후 보고의 기준으로 유지한다.

현재 로그에는 창 제목, 전체 화면과 전체 페이지 내용이 없고, 수집 범위도 앱별로 다르다. AI는 이를 고려해 관측한 행동과 업무에 대한 해석을 구분한다. ‘전송’ 클릭을 전송 성공으로, 조회 기록을 문제 해결 완료로 바꾸지 않는다. 프로그램 활성 시간은 관측 시간으로 표시하며, 업무별 시간은 관련 구간을 연결할 수 있는 경우에만 추정 근거와 함께 제공한다.

03

2일 구현 범위

해커톤 2일 동안 구현해 보고 싶은 주요 기능은 무엇인가요?

기존 WorkMemory 수집기를 활용해 짧은 실제 로그 → 업무 카드 → 빠뜨린 일 확인 → 근거가 연결된 주간보고를 필수로 완주한다. 먼저 현재 로그의 입력·클릭 맥락에 업무 의미를 복원할 정보가 충분한지 확인한다. 수집 기반이 있다는 사실과 AI 분석의 유용성이 입증됐다는 사실은 구분한다.

우선순위 구현 항목 완료 기준
필수 실제 로그의 업무 카드 생성 지원을 확인한 Chrome 테스트 페이지·접근성 테스트 앱의 기록으로 업무 후보와 유효한 근거 제시
필수 간단한 검토·확인 저장 이름 수정·잘못된 연결 제외·선택 카드 묶음 확인, 수정 내용 유지
필수 주간보고 한 종류 확인 업무로 초안 생성, 업무 항목별 근거 열기, 수정·저장·Markdown 내보내기
선택 반복 업무와 개선 후보 짧은 실제 작업 또는 별도 누적 시연 자료에서 반복 묶음 한 개와 근거 제시
선택 월간 보고와 고급 편집 같은 확인 업무의 기간 확장, 합치기·분리, 문장별 상세 근거

1일 차 중간까지 서로 다른 짧은 업무의 실제 입력·클릭을 수집하고, 실제 모델이 유효한 근거를 가진 업무 후보를 반환하는지 확인한다. 의미를 복원하기 어려우면 원문을 더 많이 수집하기에 앞서 업무 범위와 지원 환경을 좁힌다. 이어서 간단한 수정·확인 저장을 구현한다. 2일 차에는 주간보고와 근거 열기·내보내기를 완성하고, 핵심 흐름이 동작한 뒤 선택 기능을 추가한다.

주간보고의 실제 수집 자료는 포함된 날짜와 범위를 표시하며, 짧은 시연을 실제 한 주 전체의 기록처럼 제시하지 않는다. 여러 날의 흐름과 월간 확장은 별도의 가상 누적 자료로 보여주고 출처를 표시한다. 실제 메신저·IDE 호환성과 하루 연속 기록은 아직 검증 전이므로 필수 시연에 의존하지 않는다. 정기 자동 생성, 반기 평가노트, 연간 목표 연결, 팀 분석과 외부 업무 시스템 연동은 후속 확장으로 둔다.

대표 시연은 다음 순서로 진행한다.

  1. 평소처럼 작업: 기밀 없는 테스트 웹페이지·접근성 테스트 앱에서 조회·응답 작성을 수행한다. 다른 목적의 작업과 같은 번호를 쓰는 별도 작업도 섞는다.
  2. 발견의 전후 비교: 시연자가 기억으로 적은 목록과 실제 기록에서 AI가 복원한 업무 후보를 나란히 보여준다. 계획된 시연의 비교임을 밝힌다.
  3. 짧게 확인: 잘못 연결된 항목 하나를 제외하거나 제목을 고친 뒤 선택 카드 묶음을 확인한다. 원본은 필요한 카드에서만 연다.
  4. 보고에 반영: 확인된 지원 업무가 포함된 주간보고를 생성하고, 보고의 업무 항목에서 카드와 원본으로 돌아간 뒤 저장한다.
  5. 누적 시 더 보이는 것: 선택 구현이 완료되면 별도 누적 시연 자료로 반복 지원업무와 안내문 검토 후보를 보여준다. 월간도 같은 업무 기억의 기간 확장으로 설명한다.

기대효과와 검증

이 아이디어의 주요 사용자는 누구이며, 어떤 기대효과가 있나요?

첫 사용자는 조회·문의 응답 작성이 반복되고 주간보고를 작성하는 사내 시스템 운영·지원 담당자다. 입력·클릭의 의미를 관측할 수 있는 Windows·Chrome 환경에서 시작한다. 개발자·기획자 등 다른 직무로의 확장은 해당 도구와 데이터의 복원 품질을 확인한 뒤 진행한다.

사용자의 상황 기대효과 검증 방법
짧은 업무가 기록에서 자주 빠짐 미처 적지 못한 일을 떠올릴 단서 제공 AI 확인 전 작성한 업무 목록과 비교해 유용하게 추가된 업무 확인
여러 앱의 행동을 다시 정리해야 함 업무 단위의 하루 목록 제공 사용자가 작성한 기준 목록과 업무 카드의 정확성·누락 및 수정 부담 비교
주간·월간 보고 때 기억을 다시 모음 확인한 업무를 보고 초안으로 재사용 수동 작성 시간과 AI 초안 검토·수정까지의 시간 비교
비슷한 조회·안내를 반복함 개선할 업무를 발견할 기회 제공 사용자가 유효하다고 판단한 반복 묶음과 실행해볼 제안 확인
조직에서 작은 지원업무의 실체를 알기 어려움 사용자가 선택한 요약으로 반복 문의와 공통 안내·자동화 검토 대상을 설명할 근거 확보 선택해 내보낸 요약이 개선 우선순위 논의에 도움이 되는지 검토

해커톤에서는 업무 묶음의 정확성·누락, 잘못된 연결을 고친 횟수, 근거의 타당성과 전체 검토 시간을 확인한다. 계획된 테스트는 기능·복원 품질을 검증하며, 실제로 잊은 업무의 발견과 보고 시간 절감은 별도의 사용자 작업으로 확인한다. AI를 보기 전 작성한 목록에서 빠졌지만 실제 수행했다고 확인한 일을 집계하고, 수동 보고와 AI 활용 시의 기록 확인·수정·보고까지 총시간을 비교한다. 최초 수집 설정 시간도 별도로 기록한다. 주간보고 작성 시간 50% 감소는 실측 전 검증 목표이며 달성한 효과로 제시하지 않는다.

로그만으로 모든 업무를 관측할 수 없으므로 오프라인 업무나 미지원 앱의 작업은 사용자가 선택적으로 추가할 수 있게 한다. 활동량·입력 횟수·유휴 시간을 개인의 생산성 점수로 환산하지 않는다. 반복 업무 개선의 효과는 실제 적용과 후속 사용 기간이 필요하므로 해커톤의 발견·제안 검증과 나누어 측정한다.

필요 지원 사항: 사용할 AI 모델의 호출 권한과 접속 환경, 기밀 없는 테스트 작업을 수행할 Windows·Chrome 환경, 업무 복원과 보고 초안을 검토할 사용자 협조가 필요하다. 사내 자료를 활용할 경우에는 해당 환경에서 허용된 모델과 자료 범위를 확인해 적용한다.

기존의 강점인 현재 구현과 계획의 구분, 관측과 해석의 구분, 원본 근거, 사용자 수정 보존, 완료·성과의 과장 방지는 유지했다.

수정본을 심사기준·기술 검증 에이전트가 다시 읽고 핵심 가치와 범위의 개선을 확인했다. 재검토에서 남은 업무 항목별·문장별 근거 범위, 고급 편집의 우선순위, 실제 조회 limit과 건수 검사 기준의 불일치도 문서에서 정리했다.

제공된 표의 Ideathon 배점은 창의성 30%, AI 활용 적용성 30%, 효과성 40%이며, 세부항목 합은 100%다.

제공된 최종발표 표는 효과성 40%라고 적혀 있지만 해당 세부행은 기대효과 20%만 있다. 명시된 세부 배점의 합은 80%다. 나머지 20%의 항목을 추측해 추가하거나 예상 총점을 계산하지 않는다.

아직 해결됐다고 볼 수 없는 핵심 질문
  1. 현재 로그에 업무 의미를 복원할 정보가 충분한가? 수집 기반 보유만으로 답할 수 없다. 서로 다른 짧은 실제 업무와 무관한 중간 행동을 섞어 모델이 근거 있는 후보를 생성하는지 먼저 확인한다.
  2. 확인하는 수고보다 얻는 편익이 큰가? 카드 수, 잘못된 연결·누락, 수정 횟수와 검토 총시간을 측정한다. 선택 묶음 확인이 잘못된 후보를 그대로 받아들이게 하지 않는지도 본다.
  3. 새로운 발견인가, 보기 좋게 정리한 목록인가? 사용자에게 새로 드러난 업무와 반복 흐름이 무엇인지 묻는다. 시연용 가상 3건이나 계획된 작업을 실제 기억 누락 감소의 실측으로 제시하지 않는다.
  4. 주간·월간의 누적이 근거를 유지하는가? MVP는 실제 분석 범위를 표시하고 조회 한도를 넘으면 중단·기간 축소를 안내한다. 장기 확장 전 전체 기간 조회와 같은 업무의 중복 집계를 검증한다.
  5. 조직의 개선에 실제로 쓰이는가? 선택해 공유한 요약이 개선 대상을 고르는 데 유용한지 확인한다. 채택·실행·실제 효과는 서로 다른 단계로 추적한다.
발표 구성

첫 장면은 ‘Chrome을 얼마나 썼는가’보다 **‘각각의 조회·응답이 내가 반복해서 맡고 있던 지원업무였다’**는 발견에 둔다. 이어서 실제 로그의 업무 후보, 잘못된 연결 한 개의 수정, 확인한 업무가 반영된 주간보고와 근거 열기를 보여준다.

누적 반복 분석과 월간은 선택 기능으로 보여주되, 준비한 장기 자료의 출처와 실제 구현 여부를 표시한다. 기능을 넓게 보여주는 것보다 실제 로그에서 유용한 업무 의미가 만들어지는 한 흐름을 완성하는 것을 우선한다.
